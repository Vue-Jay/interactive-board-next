# Lektrus на Timeweb Cloud

**Статус:** перенос основного приложения начат. Собственный backend и подключение штатного интерфейса проверяются в отдельной миграционной ветке. Это ещё не production-развёртывание.

Текущий сайт Timeweb и рабочий проект Supabase не переключались. Пользователи, доски и файлы из Supabase пока не переносились. Не запускайте конфигурацию ниже на рабочей базе.

## Единая архитектура

После завершения миграции должен остаться один Lektrus:

- обычное приложение и редактор доски из `src/appEntry.tsx`;
- FastAPI для авторизации, прав доступа и серверных операций;
- PostgreSQL для аккаунтов, досок, участников и документов;
- приватный Docker volume для вложений;
- WebSocket для уведомлений о версиях документов и совместной работы;
- Caddy для HTTPS, раздачи фронтенда и проксирования API.

Отдельная страница `/selfhost-pilot` удалена. Новый backend подключается к штатному интерфейсу через настройки сборки:

```dotenv
VITE_LEKTRUS_BACKEND=selfhost
VITE_LEKTRUS_API_ORIGIN=https://ваш-домен
```

Если переменная `VITE_LEKTRUS_BACKEND` не задана, существующий Supabase-режим не меняется.

## Уже подключено в основном приложении

- Вход, регистрация с выбором «Я учитель» / «Я ученик», подтверждение email и обновление JWT-сессии.
- Роли и статус учётной записи из PostgreSQL.
- Список досок, создание, переименование, перемещение в корзину.
- Получение доступа к доске, приглашения по email и управление участниками.
- Штатный редактор Lektrus: чтение и сохранение родного формата документа, контроль версии и обработка конфликта сохранения.
- Загрузка и чтение вложений через приватное хранилище backend.

## Backend и инфраструктура

- PostgreSQL 17.
- FastAPI с проверкой JWT и ротацией refresh-токенов.
- Проверка прав владельца, редактора и наблюдателя на сервере.
- Версионирование документов с optimistic concurrency control.
- Приватное файловое API: авторизованные GET/HEAD/POST, потоковая передача, SHA-256, ETag и Range.
- Docker Compose: PostgreSQL и API находятся во внутренней сети; наружу опубликованы только HTTP/HTTPS порты Caddy.
- Импортёры данных Supabase Postgres и Storage с dry-run по умолчанию и проверкой целостности.

## Что ещё нужно перенести

До переключения пользователей обязательны:

- Студенты, классы, задания, расписание, учебные материалы и остальные предметные данные.
- История действий, комментарии, чат, уведомления и ссылки общего доступа.
- Администрирование аккаунтов, восстановление пароля и гостевой доступ.
- Полная синхронизация редактора: присутствие участников, курсоры, совместные штрихи, перемещение и трансформации объектов в реальном времени.
- Все используемые таблицы, RPC, фоновые задачи и политики доступа, которые сейчас завязаны на Supabase.
- Импорт существующих аккаунтов, досок, связей, документов и всех файлов Storage.
- Проверка восстановления из резервной копии, безопасности, нагрузки и работы с двух и более устройств.

Сейчас основной редактор сохраняет документы на собственный backend и получает уведомления о новых версиях. Полная низколатентная совместная работа ещё не подключена.

## Где размещать

Обычный виртуальный хостинг Timeweb Optimo подходит для статической части сайта, но не для постоянно работающего FastAPI/ASGI backend. Для этой конфигурации нужен **Timeweb Cloud VPS**.

VPS пока не создан и не оплачен. Перед развёртыванием нужны:

1. VPS с Docker Engine и Docker Compose.
2. Домен и DNS A-запись на публичный IP VPS.
3. Доступность входящих портов 80 и 443.
4. Уникальные секреты PostgreSQL и JWT.
5. SMTP для подтверждения email и приглашений.
6. Резервная копия исходной базы и Storage.

## Развёртывание после подготовки VPS

1. Собрать фронтенд с `VITE_LEKTRUS_BACKEND=selfhost` и `VITE_LEKTRUS_API_ORIGIN=https://ваш-домен`.
2. Подготовить `.env` по образцу `.env.example`. Не помещать секреты в Git.
3. Проверить конфигурацию Compose и Caddy.
4. Запустить сервисы на отдельной пустой базе.
5. Проверить health endpoint, регистрацию, вход, создание доски, сохранение документа и загрузку вложений.
6. Выполнить dry-run импорта Supabase, сверить отчёты, затем отдельно выполнить перенос базы и Storage.
7. Проверить количество записей, UUID, права, размеры и SHA-256 файлов.
8. Провести двухпользовательскую и мобильную проверку, проверить backup/restore.
9. Только после успешной приёмки переключить основной домен.

## Команды проверки

Из корня репозитория:

```bash
docker compose -f deploy/selfhost/compose.yaml config
python -m compileall -q server
```

Полные API, PostgreSQL, WebSocket и frontend-проверки выполняются GitHub Actions. Успешная CI-сборка сама по себе не означает, что backend уже развёрнут на Timeweb или что данные Supabase перенесены.
