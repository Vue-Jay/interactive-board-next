# Lektrus на Timeweb Cloud VPS

**Цель:** одно основное приложение Lektrus, работающее на собственной инфраструктуре без Supabase.

**Текущий статус.** Штатный интерфейс Lektrus подключён к собственному API для перечисленных ниже сценариев. Перед переключением основного домена остаются проверка на VPS и перенос функций из списка ниже.

## Итоговая архитектура

- Один фронтенд Lektrus из `src/appEntry.tsx`, без отдельного тестового приложения.
- FastAPI: авторизация, права доступа, доски, образовательные данные и файловые операции.
- PostgreSQL: аккаунты, роли, доски, документы, ученики, задания, расписание и занятия.
- Приватный Docker volume: вложения и файлы досок.
- WebSocket: совместная работа в редакторе.
- Caddy: HTTPS, раздача фронтенда и проксирование API.
- Docker Compose: единый запуск сервисов на Timeweb Cloud VPS.

Сборка штатного приложения подключается к собственному API:

```dotenv
VITE_LEKTRUS_BACKEND=selfhost
VITE_LEKTRUS_API_ORIGIN=https://ваш-домен
```

При таком режиме клиент должен использовать собственную инфраструктуру. Оставшиеся обращения к Supabase будут устраняться до релизного переключения.

## Новая база и аккаунты

Создаём чистую PostgreSQL-базу. Старые аккаунты, доски, документы и файлы Supabase не импортируются. После запуска пользователи регистрируются заново.

Первый администратор назначается по переменной окружения `LEKTRUS_BOOTSTRAP_ADMIN_EMAIL`. Первый подтверждённый аккаунт с точно совпадающим адресом получает права администратора и роль преподавателя. Последующие регистрации не получают административных прав. Подтверждение почты обязательно.

Для первоначального запуска указывается адрес владельца системы:

```dotenv
LEKTRUS_BOOTSTRAP_ADMIN_EMAIL=yahaus04@gmail.com
```

Эту настройку задают только в серверном `.env`, не в Git. Пароль выбирается самостоятельно при регистрации. В переписку его передавать не нужно.

## Что уже подключено к собственному API

- Регистрация преподавателя/ученика, подтверждение email, вход, выход и обновление JWT-сессии.
- Восстановление пароля через одноразовую ссылку с ограниченным сроком действия и отзывом активных сессий.
- Список досок, создание, переименование, удаление в корзину.
- Приглашения, управление участниками доски и ссылки доступа с паролем, сроком действия и лимитом входов.
- Штатный редактор: загрузка и сохранение родного документа Lektrus, контроль версий и разрешение конфликтов.
- Приватная загрузка и скачивание вложений.
- Обсуждения на доске: комментарии и ответы, участники для упоминаний, обновление обсуждений через API.
- Список учеников, заметки и метки, история занятий.
- Задания: создание, сдача, проверка, оценка и отзыв.
- Расписание, повторяющиеся занятия и управление статусами.
- Начало и завершение занятия с сохранением результата и домашнего задания.
- Присутствие участников, курсоры, рукописные штрихи, выбор и трансформации объектов в реальном времени.
- Категории и классы досок, учебные материалы, личные чаты и уведомления.
- Настройки и личные данные профиля, административная панель, заявки преподавателей и управление тарифами.

## Что ещё обязательно завершить до релиза

- Перенести гостевой вход, восстановление и окончательное удаление досок из корзины, журнал действий и оставшиеся сценарии.
- Удалить все оставшиеся обращения к Supabase из релизной конфигурации, включая скрытые фоновые и вспомогательные операции.
- Для нескольких процессов API потребуется общий канал доставки realtime-событий. Конфигурация одного VPS запускает один процесс API.
- Проверить резервное копирование и восстановление PostgreSQL и файлового хранилища.
- Провести проверку полного пользовательского сценария на реальном VPS: регистрация, вход с двух устройств, доски, вложения, совместное редактирование, задания, расписание и администрирование.

Наличие успешной CI-сборки не означает, что перечисленные функции уже перенесены или что VPS запущен.

## Размещение

Для постоянно работающего FastAPI backend нужен **Timeweb Cloud VPS**, а не обычный виртуальный хостинг.

На момент подготовки этой конфигурации VPS ещё не развёрнут и не оплачен. Для запуска понадобятся:

1. Timeweb Cloud VPS с Docker Engine и Docker Compose.
2. Домен и DNS A-запись на IP VPS.
3. Открытые входящие порты 80 и 443.
4. Уникальные пароли PostgreSQL и секрет JWT.
5. SMTP для подтверждения email, восстановления доступа и приглашений.
6. Серверный `.env` с настройками домена, почты и адресом первого администратора.

## Запуск на чистой базе

1. Подготовить VPS и DNS.
2. Создать серверный `.env` по образцу `.env.example`. Секреты не добавлять в Git.
3. Включить SMTP и регистрацию только после проверки почтовых настроек.
4. Из каталога `deploy/selfhost` запустить `docker compose up -d --build --wait`. Compose соберёт штатный фронтенд с заданным доменом, запустит PostgreSQL и применит схемы перед открытием API. При повторном запуске применяются только новые SQL-файлы, а база и файлы остаются в постоянных томах.
5. Проверить `/app` и `/api/v1/health` на тестовом домене.
6. Зарегистрировать владельца с адресом `yahaus04@gmail.com`, подтвердить email и проверить права администратора.
7. Проверить регистрацию обычного преподавателя и ученика: административные права им не выдаются.
8. Завершить перенос функций из списка выше и провести сквозные проверки.
9. После приёмки переключить основной домен на VPS.

## Локальные проверки

Из корня репозитория:

```bash
docker compose -f deploy/selfhost/compose.yaml config
python -m compileall -q server
```

API, PostgreSQL, WebSocket и frontend-проверки выполняются в GitHub Actions. Эти проверки не заменяют испытания на реальном VPS.
