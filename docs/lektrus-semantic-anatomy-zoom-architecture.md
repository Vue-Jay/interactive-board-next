# Lektrus: непрерывный семантический зум анатомии (план замены растрового спрайта)

**Статус:** архитектурное решение, ещё НЕ реализованное в новом инструменте «Анатомия человека». 
**Точка внедрения:** `src/LektrusHumanAnatomy.tsx`, `src/lektrusHumanAnatomyModel.ts`.
**Цель:** произвольный дробный зум и панорамирование от целого организма к тканям и клеткам без миллиона вручную нарисованных кадров, с видимой преемственностью формы и с проверяемой биологической достоверностью.

## 1. Почему текущий подход не работает

- Новый `LektrusHumanAnatomy` сейчас показывает семь фиксированных пластин из `human-seven-systems-clean.webp`: каждый кадр лишь 360×600, максимальная камера 3.25×; при увеличении не появляется новая информация.
- Старый `LektrusBioContinuousHuman` уже поддерживает дробную глубину, anchor-preserving zoom и смешивание слоёв, но много раз переклеивает **несвязанные изображения** одного условного органа; размытые переходы не заменяют анатомическую регистрацию.
- Сильный зум по произвольной области не может научно корректно «дорисовывать» неизвестные структуры или выдавать чужую микрофотографию за ту же точку наблюдения.

**Решение:** одна камера + пространственное дерево биологических сущностей + мультиразрешённые изображения и переиспользуемые типовые модели тканей/клеток. Число ступеней масштаба не равно числу авторских рисунков.

## 2. Модель мира

Единый объект `AnatomyScene` содержит неизменяемую систему координат одного организма (body-local coordinates) и дерево `AnatomyNode`:

```ts
type AnatomyNode = {
  id: string;                    // human.skin.shoulder, human.lung.right, ...
  parentId?: string;
  systemId: string;
  semanticType: "body"|"system"|"organ"|"region"|"tissue"|"cell";
  transformToParent: Matrix2D;   // привязка к родительской сцене
  bounds: Rect | Polygon;        // настоящая область выбора/клиппинга
  landmarks: Record<string, Vec2>;
  visibilityLogScale: [number, number]; // пороги детализации, не страницы
  renderSource: {
    kind: "sprite"|"tile-pyramid"|"mesh"|"procedural-template"|"specimen";
    assetId?: string; templateId?: string; specimenId?: string;
    sourceScale?: number; // только при проверенной калибровке
  };
  provenance: "reconstruction"|"representative-specimen"|"registered-sample";
  children: string[];
};
```

Система органов НЕ имеет отдельной камеры. Выбор вкладки только скрывает чужие узлы. Переходы между дочерними узлами используют `transformToParent` и локальные ориентиры (`landmarks`), поэтому выбранная точка остаётся под курсором при увеличении.

## 3. Рендеринг, а не набор кадров

- **Общий план и органы:** качественные растровые 2D/2.5D-слои, нормализованные к единой геометрии тела; в будущем возможны mesh/cutaway и аппаратная отрисовка. Слои систем включаются независимо и не меняют текущую камеру.
- **Большие детализации:** пирамиды изображений (mip levels / deep-zoom tiles). Камера загружает только видимые плитки подходящего разрешения; текстура повышается постепенно, а не перепрыгивает через отдельные полноэкранные кадры. Пирамида НЕ создаёт новые биологические детали, если в исходнике их не было.
- **Повторяющаяся микроструктура:** ограниченное число научно проверенных процедурных шаблонов ткани (эпидермис, дерма, альвеолярный эпителий, кишечный эпителий, поперечнополосатое мышечное волокно и т.п.). У шаблонов параметры толщины, частоты, строения и разные seed; типовые клетки и сосуды размещаются по правилам, без ручной отрисовки каждой.
- **Сложные уникальные структуры:** один качественный иллюстрированный organ/cell detail или калиброванный препарат на **узел типа**, а не на каждый пиксель организма. Пропуски помечаются как неописанные, никогда не заполняются случайной «похожей» тканью.

Для React-приложения рекомендуется оставить React для редактора и контролов, а графическую сцену вынести в `AnatomyRenderer` на PixiJS/WebGL с Canvas2D fallback (после проверки стоимости зависимости и GPU на Android). Поддерживать батчинг спрайтов, offscreen culling, LRU-кэш текстур, lazy loading и лимит мобильного бюджета памяти. OpenSeadragon уместен для отдельных очень больших сканов/гистологических пирамид, но НЕ заменяет сценограф, потому что не знает, что такое лёгкое или кератиноцит.

## 4. Непрерывный зум и LOD

Камера хранит `{centerX,centerY,logScale}`. Колесо/жесты изменяют **logScale непрерывно**, а `screen -> world` под выбранной точкой остаётся инвариантным. Движение камеры и альфа-переходы реализуются на отдельном render loop (не 60 React-перерендеров дерева органов в секунду).

Графические узлы имеют перекрывающиеся интервалы масштаба; во время перехода родитель и дочерний вид на коротком диапазоне присутствуют одновременно. Граница перехода привязана к одной пространственной области, не к центру окна. При возврате назад происходит обратный переход без рывка и потери координаты.

**Важное научное условие.** «Кожа снаружи → поперечный срез кожи» не является буквальным оптическим увеличением одной фотографии. Для этого вводится явно обозначаемый режим виртуального среза (`surface/cutaway/microstructure`), сохраняющий географическую привязку, но не выдающий реконструкцию за настоящую оптическую съёмку. «×/µm» показывать только на калиброванных данных, иначе «уровень детализации».

## 5. Первый настоящий маршрут: покровная система

| Диапазон | Визуализация | Поведение |
| --- | --- | --- |
| Организм | Весь нейтральный человек со знакомыми пропорциями | Та же общая камера семи систем |
| Плечо/область кожи | Высокодетализированная региональная текстура | Приближается именно участок под курсором, не весь портрет |
| Поверхность | Повторяемая микротекстура пор, волосков и складок с региональными параметрами | Новая текстура плавно накладывается по мере роста масштаба |
| Виртуальный срез | Один точный образец слоёв эпидермиса, дермы, гиподермы; фолликулы, железы, сосуды и нервы | Переход ясно отмечен как модельный срез; общий якорь не теряется |
| Клетки/структуры | Типовые кератиноциты, волокна и сосуды из переиспользуемых научных шаблонов | Клетки и детали возникают по LOD без отдельного изображения на каждый шаг |

На других участках тела те же шаблоны повторно используются с заданными биологическими различиями (например, волосистая/безволосая кожа, толщина рогового слоя); неоднозначные области не выдавать за точные личные анатомические данные.

## 6. Масштабирование на других организмов

`AnatomyNode` и `renderSource.templateId` становятся частью общего каталога **типов органов и тканей**, а вид даёт морфологию, параметры и разрешённые различия.

Пример: `mammal.skin.epidermis` переиспользуется человеком и кошкой с разными региональными параметрами; лист растения использует отдельные растительные клеточные шаблоны и НЕ наследует кожу млекопитающих. Каждый новый вид требует анатомического скелета/расположения основных органов, но не требует заново рисовать все эпителиальные клетки.

## 7. Внедрение без повреждения существующих объектов

1. Ввести `AnatomySceneGraph`, `AnatomyCamera`, `SemanticLODResolver` и тесты преобразования локальных/world координат. Старый формат `bio-anatomy` сохранять; дополнять необязательным `atlasVersion` и `selectedPath`.
2. Сделать пилот покровной системы: **один зарегистрированный макрорегион → одна региональная текстура → модельный срез → шаблоны эпидермиса**. Вспомогательные иллюстрации не являются последовательными кадрами анимации.
3. Подключить рендерер к текущему отдельному окну `LektrusHumanAnatomy`; отключить жёсткий предел 3.25× только там, где реально есть глубокие источники; для прочих систем сохранить честное ограничение.
4. Добавить кеш видимых тайлов, отмену загрузок при перемещении, низкое разрешение на дальнем плане и lazy-detail на ПК/Android. Все ресурсы версионировать и готовить офлайн-пакетами.
5. После успешного пилота заполнить органный граф для нервной, дыхательной, кровеносной, пищеварительной, мочевыделительной и опорно-двигательной систем. Затем отдельно видовые графы животных и растений.

## 8. Критерии приёмки

- При переключении систем камера, точка под курсором, панорамирование и масштаб **не меняются**.
- Плавный зум без видимого скачка, прогрессивная подгрузка детализации и отсутствие пустого экрана на пороге загрузки.
- Точки входа в срезы/клетки соответствуют настоящим родительским структурам; чужая ткань не подменяется похожей картинкой.
- Сцена остаётся управляемой при перетаскивании и двухпальцевом зуме на Redmi Note 8 Pro/Android 11 и на ПК; целевой бюджет: 60 fps на ПК, не ниже 30 fps на тестовом мобильном устройстве при типовой сцене, память контролируется.
- Тесты: преобразование координат, invariance под курсором, LOD при дробном масштабе, реверсивность зума, видимость только одной системы, корректность границ и provenance, мобильный memory/performance smoke test.
- Старые сохранённые атласы открываются после обновления; новая детализация не требует Supabase и доступна в локальной сборке при установленном пакете изображений.

**Не цель:** симулировать физически точную многомиллиарднократную микроскопию любого произвольного пикселя. Воспроизводимая школьная модель отличается от измеренного микропрепарата, и интерфейс должен показывать эту разницу.

## Технические справочники

- OpenSeadragon: multi-resolution TileSource / Flexible Pyramids.
- PixiJS v8: Container scene graph, batched sprites, GPU-level render groups and texture-cache techniques.
- Allen Cell Explorer: volumetric models and registered 3D cell data (пример реальной научной базы вместо угадывания ультраструктуры).
