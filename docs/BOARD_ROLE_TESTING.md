# Роли на доске Lektrus: правила и проверка

## Принцип

Права на **самой доске** у гостя и зарегистрированного ученика одинаковы. Для обоих действуют ограничения школьного режима и те же разрешения, выданные через приглашение. Гость отличается временной анонимной авторизацией и отсутствием постоянного аккаунта, а не набором инструментов на доске.

Доступ **«Редактирование» / «Только просмотр»** независим от учебной роли. Ссылка для просмотра остаётся только для просмотра и у преподавателя, и у ученика, и у гостя.

| Действие на доске | Преподаватель с правом редактирования | Ученик с правом редактирования | Гость с правом редактирования | Любой пользователь с доступом только на просмотр |
| --- | --- | --- | --- | --- |
| Рука, выделение, петля, масштаб, просмотр | Да | Да | Да | Да |
| Карандаш, маркер, ластик, текст, стикеры, простые фигуры, линии, комментарии | Да | Да | Да | Нет |
| Учебные задания: ответы на тесты/чек-листы, карточки | Да | Да | Да | Только просмотр |
| Рисование, метки и раскрашивание контурной карты | Да | Да | Да | Нет |
| Изменение задания преподавателя, типа карты и его разрешений | Да | Нет | Нет | Нет |
| Новые графики, конструкторы заданий, формулы, таблицы, шторки | Да | Нет | Нет | Нет |
| Фото/PDF | Добавление на доску | Отправка преподавателю на одобрение | Отправка преподавателю на одобрение | Нет |
| Управление предметом, приглашениями и участниками | Владелец доски | Нет | Нет | Нет |
| Изменение учительских защищённых объектов, точек графика и сетки | Да | Нет | Нет | Нет |

Инструменты, защищённые от ученического структурного редактирования, перечислены в `src/lektrusBoardRolePreview.ts`. Единую модель используют интерфейс, клавиатурные сокращения и обработчики объектов.

## Настройки разработчика

Доступны администратору в настройках разработчика **на открытой доске**: кнопки **Преподаватель**, **Ученик**, **Гость** и **Вернуть настоящую роль**. Роль сбрасывается при закрытии/смене доски и не сохраняется в аккаунте.

Это только имитация пользовательских инструментов. Она не меняет реальную роль пользователя, разрешения на сервере, доступ по приглашению, наличие аккаунта и авторизацию Supabase. При реальном доступе «Только просмотр» имитация преподавателя не позволяет записывать данные.

## Проверка руками на двух сессиях

1. Открыть одну тестовую доску как преподаватель-владелец, вторым браузером войти как зарегистрированный ученик через ссылку «Редактирование».
2. Повторить вторую сессию анонимным гостем по такой же ссылке: доступные инструменты, видимость элементов, ответы на тесты и контурная карта должны совпадать с учеником.
3. Отправить изображение/PDF из обоих ученических режимов. Пока преподаватель не одобрил, файл не должен добавиться на доску. Проверить одобрение и отклонение.
4. Учеником и гостем попытаться переместить/удалить вершины учительского графика, изменить настройки контурного задания и его основу, создать таблицу, тест и формулу: операции должны быть недоступны.
5. На каждом из трёх аккаунтов открыть ссылку «Только просмотр»: перемещение камеры, рука, выделение и петля работают, изменение любого объекта и загрузка файлов запрещены.
6. Администратору поочерёдно включить три тестовые роли на той же доске, убедиться, что редакторы закрываются при переключении, защищённые инструменты исчезают/блокируются, а кнопка сброса восстанавливает настоящие возможности.
7. Двум пользователям одновременно менять разные разрешённые объекты, проверяя Realtime, конфликт версий и сохранение после обновления страницы.

## Автоматическая проверка

`node scripts/test-lektrus-board-role-preview.mjs`

Проверяются 96 комбинаций реальной роли на доске, учебной роли, гостевого статуса, admin maintenance и тестовой роли. Дополнительно сравниваются действия ученика и гостя, включая создание объектов, защиту заданий, доступ на просмотр и основные UI-обработчики.

## Серверная защита

В Supabase анонимный вход создаёт авторизованного пользователя. Реальное право записи проверяется членством в доске (owner/editor) через `can_edit_board`, а не переключателем разработчика. Сохранение документа `save_board_document` также вызывает `can_edit_board` и проверяет версию документа для защиты от конфликтов.

Тестовый переключатель **никогда** не должен записывать реальную роль, подменять сессию или обходить RLS. Проверка UI не заменяет финальный тест в двух браузерах со своими реальными сессиями.
