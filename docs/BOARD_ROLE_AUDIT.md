# Lektrus: проверка ролей доски

Дата проверки: 25.10.2026. Проверяемая ветка: `main`.

## Разделение ролей

Роль аккаунта (`teacher` / `student`) и роль доступа к конкретной доске (`owner` / `editor` / `viewer`) независимы.
Реальная гостевая сессия Supabase является анонимной авторизацией, а не дополнительной ролью в `board_members`.
Переключатель **Настройки разработчика → Проверка роли на доске** доступен только администратору и действует в памяти текущего экземпляра доски. Он **не меняет** `auth.uid()`, JWT, данные `profiles`, `board_members` или права Supabase.

| Режим интерфейса | Создание заданий | Обычное рисование при доступе редактора | Выполнение контурной карты | Управление участниками |
| --- | --- | --- | --- | --- |
| Преподаватель | Да при реальном разрешении на редактирование | Да | Да | Только реальный владелец |
| Ученик | Нет | Да | Да, только слои ответов | Нет |
| Гость (тест) | Нет | Да | Да, только слои ответов | Нет |

Любая реальная роль `viewer` ограничивает запись во всех трёх сценариях, сохраняя навигацию по доске. Гость и зарегистрированный ученик имеют один и тот же набор функций при одинаковом праве доступа к доске. Режим разработчика не повышает серверные права пользователя с ролью `viewer`.

## Проверка интерфейса

- Изменение роли завершает активные жесты, закрывает привилегированные редакторы и переключает инструмент на «Выбор».
- Действующий режим постоянно обозначен сверху, есть возврат к настоящей роли.
- Инструменты создания и редакторы тестов, карточек, чек-листов и учебных таблиц защищены от сохранения в режиме ученика.
- Студент не может менять задание, территорию, подложку и права инструментов контурной карты. Его метки, штрихи, раскраска и положение карты остаются доступными.
- Редактирование названия, предмета, приглашение участников и общие настройки не доступны в режимах ученика/гостя.
- Серверное сохранение и проверка реальных прав по-прежнему выполняются без использования поля тестовой роли.

Автоматизированная матрица: `scripts/test-lektrus-board-role-preview.mjs` (96 сочетаний режима, роли доски, роли аккаунта, реального гостевого статуса и административного обслуживания; проверка более 3 800 сочетаний разрешений и действий). Подключена к `npm run test:ui`.

## Результаты read-only аудита Supabase

Проект: `Lectrus`, 25.10.2026. Проверены `pg_policies`, `pg_class` и определения `can_access_board`, `can_edit_board`, `save_board_document`, `admin_save_board_document`, `get_my_account_access`. Применено точечное исправление безопасности представления `board_comment_mentions`: `security_invoker=true`; `anon` лишён доступа к представлению, `authenticated` имеет только `SELECT` с соблюдением RLS `board_comments`.

- На `boards`, `board_members`, `board_invites`, `board_documents`, `profiles` включён RLS.
- `board_documents` доступен на чтение при `can_access_board`, запись при `can_edit_board`.
- `save_board_document` также проверяет `can_edit_board` и использует проверку версии для конкурентного сохранения.
- `can_edit_board` **не проверяет профильный статус teacher/student** и не контролирует поля внутри JSON-документа. Поэтому настоящий ученик с членством `editor` может через прямой API пытаться изменить учительские объекты. Ограничения frontend не являются серверной защитой от умышленного обхода. Для строгой модели доступа нужен серверный валидатор диффа объектов.
- `admin_save_board_document` проверяет серверный признак администратора. Клиентский переключатель не способен повысить его.

Supabase Security Advisor выявил 73 предупреждения о публичной доступности к вызову `SECURITY DEFINER` RPC. Представление `board_comment_mentions`, ранее вызывавшее предупреждение `security_definer_view`, исправлено через `security_invoker` и ограничение прав. Остальные предупреждения требуют индивидуальной ревизии `EXECUTE`/RLS, **не являются автоматически доказанными сценариями эксплуатации**. Не следует массово отзывать привилегии без проверки гостевого входа, приглашений и административных процедур.

Справка: https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable

## Ограничения проверки

Реальные тесты сохранения под тремя независимыми JWT/аккаунтами, браузерный тест на мобильных устройствах, прогон `npm run build` и `npm run test:ui` в CI здесь ещё не подтверждены. Включённые в репозиторий тесты необходимо выполнить в среде с установленными зависимостями. Без отдельной серверной защиты JSON-документа нельзя считать ограничения ученика устойчивыми к прямым HTTP-запросам.
