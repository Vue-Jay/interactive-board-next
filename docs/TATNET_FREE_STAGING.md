# Lektrus: безопасная пробная публикация на TatNet Free

**Назначение:** сначала проверить Lektrus на полностью бесплатной инфраструктуре TatNet,
не переключая рабочий домен и не копируя пользователей или данные production.

## Выделенные ресурсы

| Ресурс | Тестовая настройка |
| --- | --- |
| Исходники | GitHub `Vue-Jay/interactive-board-next`, ветка `staging/tatnet-free-20261114` |
| TatNet Apps | **Бесплатный**; тип приложения **Vite / SPA / static**, НЕ Docker и не backend |
| Сборка | `npm run build:tatnet-free` (preflight + TypeScript + Vite) |
| Публикация | каталог `dist`; HTTPS на новом `*.tatnet.app` |
| Supabase | **отдельная новая** TatNet Supabase **Free**, только для тестовых пользователей |
| Домен и база работающего сайта | **не менять** |
| Счёт и тарифы | **не подключать** Apps Basic/Pro или Supabase Pro без отдельного решения |

Существующий `Dockerfile` используется для других окружений; в TatNet Free нужно
явно выбрать пресет Vite, который раздаёт готовые файлы как статику.

Путь `/app`, `/board/:id`, `/tools/atlas` и `/tools/laboratory` должен
открываться и прямой ссылкой. Корневой `tatnet.json` задаёт SPA fallback
на `/index.html`; после первого деплоя нужно также проверить, что реальные
`/assets/*` файлы отдаются как JS/CSS, а не как HTML.

## Подключение TatNet в ChatGPT без передачи ключей

TatNet официально предоставляет **два разных OAuth MCP** подключения:

- Управление TatNet Apps и проектами: `https://mcp.tatnet.cloud/mcp`
- Управление конкретной TatNet Supabase базой: `https://mcp.tatnet.cloud/supabase/mcp`

В интерфейсе ChatGPT: **Плагины → Добавить → пользовательский сервер MCP**,
вставить адрес и выбрать OAuth. Возможность добавления зависит от доступа в ChatGPT.
Дать доступ только к **тестовому** проекту и новой тестовой базе.
Для работы со схемой тестовой базы доступ к записи потребуется отдельно.
Не пересылать в чат пароли, `service_role` или администраторские API-ключи.

Если прямое подключение MCP недоступно, безопасная альтернатива:
подключить GitHub в панели TatNet (https://min.tatnet.ru), выбрать эту
staging-ветку и создать базу через раздел Supabase. Приложение не должно
использовать production URL/ключи.

## Переменные сборки приложения (TatNet Apps → Environment)

| Имя | Значение |
| --- | --- |
| `VITE_SUPABASE_URL` | HTTPS API URL **новой базы TatNet Free** из её карточки |
| `VITE_SUPABASE_ANON_KEY` | публичный `anon` JWT / `sb_publishable_...` именно новой базы |
| `VITE_LEKTRUS_LOCAL_TEST` | `false` (или не задавать) |
| `VITE_LECTRIS_ORG_SYNC` | `false` до миграции и проверки специальных таблиц/политик |
| `VITE_TELEGRAM_URL` | необязательно, публичная ссылка на Telegram |

Переменные `VITE_*` **попадают в клиентский JS**, поэтому в них допустим
только публичный `anon/publishable` ключ. Ни `service_role`, ни токен
управления TatNet, ни пароли не могут находиться в Vite-переменных.

Гарантированный preflight `npm run build:tatnet-free` предотвращает случайное
развёртывание без сервера, через `supabase.co`, с secret/service_role ключом
или в локальном демонстрационном режиме. URL и ключ при проверке не выводятся.

## Проверка базы до открытия регистрации

1. Создать отдельную базу уровня **Free** в TatNet. Одна бесплатная база на
   аккаунт, не больше 100 МБ Postgres, 1 ГБ Storage и 5 ГБ/мес трафика.
2. Развернуть в ней **схему и RLS**, необходимые Lektrus, из файлов
   `supabase/setup.sql` и следующих версионированных SQL миграций после
   отдельной проверки их порядка, зависимостей и совместимости с TatNet.
   Не загружать SQL для production напрямую без проверки!
3. Проверить REST RPC создания доски, сохранения документа,
   выдачи доступа, RLS, Storage bucket `board-assets`, Realtime и политики
   для учеников и преподавателей. Использовать тестовые записи.
4. В Auth → URL Configuration выставить **Site URL** на выданный
   `https://<имя>.tatnet.app` и разрешить redirect адрес
   `https://<имя>.tatnet.app/app?email_confirmation=1`.
   Проверить письмо, вход, выход и повторный вход.
5. Только после этого открывать регистрацию тестовым пользователям.
   При паузе Free через 7 дней без обращений база возобновляется из панели.

Бесплатная TatNet Supabase не исполняет **Edge Functions**. Возможности Lektrus,
которым они необходимы, нельзя объявлять проверенными до отдельного анализа;
обычная работа доски использует Auth, REST RPC, Storage и Realtime.

## Приёмка на тестовом адресе

- `/`: сайт и HTTPS; `/app`: авторизация, вход по ссылке, работа после обновления.
- `/board/<id>`: открыть прямой ссылкой и после F5, рисовать, стирать,
  передвигать объект, сохранять, выполнять undo/redo.
- `/tools/atlas` и `/tools/laboratory`: открыть прямой ссылкой после F5;
  проверить карту, химическую реакцию, паузу, сохранение и повторное открытие.
- Два **тестовых** аккаунта (учитель/ученик): открыть одну доску на ПК и телефоне;
  проверить Realtime и отсутствие скачков объектов, гостевой/редакторский доступ.
- Файлы: добавить изображение/PDF в Storage, открыть со второго устройства;
  проверить политику доступа, отсутствие 401/403/404 в Network.
- Состав предметов: «Задания на доске» в биологии, информатике,
  обществознании, литературе, плюс историческая карта в истории.
- Иностранный язык: перетаскивание слов мышью и пальцем.
- Контроль: фактический размер базы, Storage, Realtime и трафик TatNet в панели.

## Переход после успешного испытания

Не переносить рабочую базу и DNS до отдельного решения. Сначала измерить
трафик на Free; будущая цель для платной базы с лимитом 250 ГБ/мес —
**не более 200 ГБ/мес с запасом**. TatNet Supabase Free можно перевести
на Pro в карточке **той же базы**, без её пересоздания. Статический сайт
при этом может продолжать работать на TatNet Apps Free.
